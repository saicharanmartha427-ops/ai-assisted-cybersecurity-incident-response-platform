# AI-Assisted Software Engineering Evidence

The Product 26 guide requires GitHub Copilot and Generative AI to be used throughout the SDLC. Keep this document with project evidence/screenshots in the final submission.

## Suggested evidence trail

1. Requirement analysis — prompt AI to convert the project brief into functional/non-functional requirements.
2. Architecture — prompt AI to propose React/Flask/database modules and review the proposal manually.
3. Prompt engineering — maintain prompts for API design, anomaly detection, UI accessibility and test generation.
4. Coding — use GitHub Copilot for repetitive React/Flask/database code, then review generated code.
5. Testing — ask AI to generate edge cases for CSV parsing, authentication and incident state transitions.
6. Debugging — document the Smart App Control native-DLL issue and the decision to create a SAC-compatible runtime.
7. Security review — use AI to identify missing authentication, authorization, validation and audit logging; manually verify every recommendation.
8. Documentation — use AI to draft README/API documentation, then manually validate against the implementation.
9. Deployment — use AI to review Docker/environment configuration and cloud deployment steps.

## Responsible AI rule

AI-generated recommendations are advisory. The system must not claim certainty, and an analyst remains responsible for response actions. The anomaly detector is a prototype and must not be represented as a production-grade SOC/EDR/IDS model.
